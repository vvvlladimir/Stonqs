# 78: The app states what it is not, and carries its notices

- Status: Accepted

## Context

The disclaimer — a portfolio tracker, not financial advice; free data sources that guarantee
nothing — existed only in the README and on the website. Neither is on screen while somebody reads
a return figure, and neither travels with a build.

Two more things were missing from the app itself. The assistant's answers are written by a model
over the user's own data and carry the usual risk of being confidently wrong, and nothing in the
panel said so; Article 50 of the EU AI Act, applicable from 2 August 2026, asks that a system
interacting with a person be built so the person knows it is one. And the app is AGPL-3.0-only but
is built from several hundred MIT, Apache-2.0, BSD and ISC components, every one of which asks that
its licence text and copyright notice travel with a copy — including a compiled one.

## Decision

The app says it itself, in the three places a figure is read, and ships the notices it owes.

- **The assistant panel carries a standing line** under the composer, and the dashboard's summary
  tile one under its text: generated by AI from your own data, can be wrong, not investment advice.
  Not a dismissible banner and not a tooltip — it is there whenever an answer is.
- **The onboarding gate says it once**, where the app is first trusted with a number, and points at
  the full wording.
- **Settings → About holds the full text**, beside the licence the app is published under and the
  list of everything it is built from.
- **A saved report leaves with one line** saying what the file is. The sentence is the frontend's
  and crosses to `report_save` as an argument, because the language is known only there
  (ADR-0023) — the host writes no wording of its own into a user's file. It is one cell on a row
  after a blank line, so a spreadsheet shows it and a parser reads the tables first.
- **A canonical export carries nothing**: the transaction file and the taxonomy file are read back
  by this app's own import, and a line the reader does not expect would cost a re-import. A file
  meant for a machine is not where a notice belongs.
- **`THIRD-PARTY-NOTICES.md` is generated**, never written: `scripts/notices.mjs` walks
  `cargo metadata` (dev-dependencies excluded, build ones kept — a proc macro's output is in the
  binary) and `pnpm licenses list --prod`, reads each package's own licence files, and groups
  identical texts under everything that ships them. It is compiled into the host, so
  `notices_save` can write it wherever the user asks on any platform; the table the About panel
  shows is a second, small generated file, so a megabyte of licence text is never in the frontend
  bundle. `node scripts/notices.mjs --check` fails in the audit workflow when a dependency changed
  without the notices being regenerated.

## Alternatives

- **A dismissible dialog at first launch.** Answered once and never seen again, which is the
  opposite of a line beside the number it qualifies.
- **The disclaimer written in the host.** It is a sentence, so it would ship in one language —
  exactly what ADR-0023 exists to prevent.
- **`cargo about` plus a JavaScript licence checker.** Two more tools to install in CI and two
  formats to merge, for a job that is one script over the two lockfiles.
- **Linking to the notices on the web.** The obligation is to the copy somebody has, and a
  desktop app that is offline still has to be able to show them.

## Consequences

- A new dependency is a regenerated notices file, and CI says so before a release does not.
- The generated list is checked in, so a fresh clone builds the About panel without running any
  tool first.
- Wording lives with the other user-visible text: `app/src/lib/legal.ts` for the exported line,
  the panels for the rest, all of it translated like anything else.
- The notices are read from what is installed locally. A package that ships no licence file is
  listed with its SPDX id and no text, which is the most the lockfile knows.
