# 96: The Windows build also ships through the Microsoft Store

- Status: Accepted

## Context

The Windows installer is not code-signed, so SmartScreen warns on every download and Smart App
Control may refuse it outright. A certificate issued to a person costs money every year and lives
on a hardware token a CI runner cannot reach.

The Microsoft Store registers an individual publisher for free and signs an MSIX package itself,
so a copy installed from it raises no warning. It installs that package read-only under
`WindowsApps`, where the updater plugin (ADR-0063) cannot replace the binary, and updates the
package itself.

## Decision

The Windows leg of `release.yml` also packs the binary `tauri-action` built into an MSIX: the
manifest and its logos are `app/src-tauri/msix/` (logos generated by `app/scripts/make-icons.sh`),
taken from the revision the workflow runs from so an older tag can be repackaged. The identity is
the one Partner Center reserved; the version is the release's with a fourth number of `0`, which
the Store reserves. `makepri` and `makeappx` from the runner's Windows SDK build it unsigned, and
it is attached to the draft as `Stonqs-windows-x86_64-store.msixupload`. A failure there costs
only that file.

`store.yml` sends that file to Partner Center through `msstore publish` when the draft is
published, so publishing stays the one act that reaches users. It signs in with an Entra
application (`MSSTORE_*` secrets).

The package depends on `Microsoft.VCLibs.140.00.UWPDesktop` for the C runtime. It does not carry
WebView2: Windows 11 ships it, and Windows 10 receives it with Edge.

## Alternatives

- A certificate of our own: signs every download, not only the Store's, but costs yearly while the
  project earns nothing, and its key cannot be used unattended.
- Submitting the signed-by-nobody `-setup.exe` by URL: the Store accepts only a signed installer.

## Consequences

A Windows user who installs from the Store sees no warning and is updated by the Store (how the
app learns of that update: ADR-0097). The direct download stays as it is, unsigned, with the
updater plugin.

A release reaches Store users only after the Store certifies it, hours to days after the GitHub
release. Windows redirects a packaged app's writes to `%APPDATA%` into the package's own storage,
so a Store copy's profiles live there.

Reopen if the direct download gets a code signature: the Store also accepts a signed installer by
URL, which would keep one package and one update path.
