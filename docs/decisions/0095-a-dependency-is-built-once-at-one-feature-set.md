# 95: A dependency is built once, at one feature set

- Status: Accepted

## Context

Cargo turns on a dependency's features by what is being built, so `cargo test -p sq-core`,
`cargo test -p sq-app` and `cargo test --workspace` build `serde`, `serde_json`, `hashbrown`,
`uuid` and the rest at different feature sets. Every variant is a separate build, and everything
above it — `sq-core` included — is rebuilt with it. Moving between a one-crate check and a
workspace check therefore recompiled the shared tree each time, locally and in CI's caches.

## Decision

A `workspace-hack` crate generated by `cargo hakari` holds each third-party dependency at the
union of the features the workspace uses, on macOS, Linux and Windows, and every member depends on
it. `.config/hakari.toml` keeps out every dependency `sq-core` and `sq-cli` do not already reach —
Tauri, tokio, the platform UI crates, wasmtime — so the hack changes only the features of what the
core already builds, never what it depends on: the layering in `CLAUDE.md` holds.

CI runs `cargo hakari generate --diff` and `cargo hakari manage-deps --dry-run`.

## Alternatives

- Cargo's `feature-unification = "workspace"` (RFC 3692): the same with no generated crate, but not
  stable on the pinned toolchain. Replace the hack with it once it is.
- No exclusions, as hakari generates by default: pulls `tauri`, `tokio` and `objc2-app-kit` under
  `sq-core`, against the one-way layering.
- Always check the whole workspace: one feature set too, but every one-crate edit pays for the
  host's graph.

## Consequences

Every `-p` build reuses one build of each shared dependency. A crate built alone compiles the
union of features, so `sq-core` on its own is slightly heavier than before; what it links is the
same set of crates.

`workspace-hack/Cargo.toml` is generated and has to be kept current: a dependency bump that moves a
feature set fails CI until `cargo hakari generate` runs on that branch, and dependabot does not run
it. A new host-only dependency that hakari wants to add goes into `final-excludes`; one that
`cargo tree -p sq-core` already shows does not. `fuzz/` builds `sq-core` by path and so builds the
hack too.
